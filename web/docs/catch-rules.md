# Size and bag limits

A free guide panel on every spot page and on `/rules`. Tap a fish (the spot's own species first, "More fish" for the
rest) and the panel shows that spot's rules in big numbers: minimum size ("Under that, put it back." underneath),
daily limit, per-boat or shared limit if any, and the area finfish total. Then one "Source: MPI" link to that rule area's
MPI page. No length input, no explanations under the numbers.

The only words kept, because they are the rule: "Under that, put it back.", "No take here. Put it back.",
"Closed here until X. Put it back." and Jackson Bay's "Whole or gutted only." Disputed rows show the stricter number,
hidden rows (stale or null) show a dash, and both get a small "check MPI" next to the source link, as do page-only
rows. Split spots show "Depends where you are" with area buttons. Lakes say "Freshwater: Fish & Game rules apply."
The footer is one line: "Guide only. Rāhui may apply. MPI data CC BY 4.0."

All notes, verification and source metadata stay in the JSON; the panel just doesn't show them. It never says
"you can keep it". It's a guide. The law is the MPI rules.

## Data

Sources, and nothing else:

* MPI area pages under `mpi.govt.nz/fishing-aquaculture/recreational-fishing/fishing-rules/` (Auckland/Kermadec,
  Central, Challenger, Kaikōura, South-East, Southland, Fiordland Marine Area).
* The Fisheries (Amateur Fishing) Rules Notice 2026 (the "notice"), linked from those pages.

Each row is `zone x species` with `minSizeCm` (number, `"none"` or `null`), `dailyLimit` (number, `"combined"` meaning
it only counts toward the area total, `"no-take"`, or `null`), shared and accumulation limits, closures as `MM-DD`
ranges, `sourceUrl`, `noticePart`, `dateChecked` and `verified: false`.

Other row fields:

* `combinedDaily` / `combinedVessel`: the combined finfish total for that zone, already the lowest that applies
  (Challenger mātaitai 10 and 30 per boat, Akaroa 10, Lyttelton 10, East Otago taiāpure 10, the Fiords 10,
  Fiordland Marine Area 20, otherwise the FMA's 20 or 30). If a species limit is higher than the total, the panel shows
  the total as the daily limit.
* `pageOnly`: the number is from an MPI area page (or a bylaw listed there), not the notice. The panel says so.
* `disputed`: MPI's page and notice disagree. We store the stricter number and the panel says "MPI sources differ,
  check MPI". These rows stay `verified: false`.
* `verified`, `verifiedBy`, `verifiedOn`, `checkStatus`: from Forecast Brain's second check on 27 Oct 2026
  (`scripts/catch-rules/second-check-2026-10-27.csv`). Only rows it matched, plus the two kingfish rows it filled in,
  are `verified: true`.

Rules in the UI:

* `null` anywhere in a row, or `dateChecked` older than 60 days: no numbers, just a link to the MPI page.
* The spot headline and Where to go show "Snapper: minimum 30 cm" from this data, and drop it for split, freshwater,
  disputed or hidden rows.
* Closures are worked out in Pacific/Auckland time.

## Boundary spots

Some spots sit on a line between areas. Instead of guessing, the spot lists every option and the panel says
"Depends where you are" and shows them all, with a toggle. Lake spots show "Freshwater: Fish & Game rules apply" and a
link, with no MPI numbers. See `SPOTS` in build.py for the options and the reasoning behind each one.

## Rebuild

```bash
python3 scripts/catch-rules/build.py --csv ../../research/catch-rules-to-verify.csv
npx tsc --noEmit && npm run build
```

Bump `CHECKED` in build.py when you've re-read the pages, otherwise rows go stale after 60 days on purpose.

## Weekly change check

```bash
pip install playwright        # uses system Chrome, no browser download needed
python3 scripts/check-mpi-rules.py           # report only
python3 scripts/check-mpi-rules.py --update  # after you've updated build.py, save the new baseline
```

It fetches each area page (Playwright, because MPI's bot wall blocks curl), pulls the "Last reviewed" date and a
SHA-256 of the text from "Last reviewed" to the page footer, and compares with the baseline. Exit 0 means no change,
1 means something changed, 2 means a page couldn't be fetched.

Limits:

* It doesn't watch the notice PDF, Gazette amendments, s186A closures or rāhui. A new notice usually changes the area
  pages too, but check the MPI news page as well.
* A text change can be cosmetic. It only tells you to look.
* If MPI tightens the bot wall it will report FAILED rather than a false "same".
* It isn't scheduled. Run it weekly by hand or put it in a cron somewhere that has Chrome.
